## 1. Продуктовый контракт

Teleiosis — персональная система самообразования: сохранить → выбрать → изучить → осмыслить → повторить → продолжить. Библиотека сохраняется как опора, но основным ежедневным входом становится «Сегодня». Целевая аудитория-гипотеза: люди, самостоятельно изучающие темы по материалам из разных источников. Ценность: не больше закладок, а больше осмысленно изученного. Продукт не проверяет объективное освоение знаний; отметки пользователя и результаты самопроверки — косвенные показатели.

### Приоритеты
- P0: «Сегодня», быстрый доступ к плану и повторению, завершение материала с необязательной рефлексией; сохранение всех старых возможностей.
- P0: долгосрочные образовательные цели и связи с материалами, повторное использование недельного плана.
- P1: подбор по времени (5/15/30/60 минут), простая очередь рекомендаций, понятный прогресс.
- P2: более глубокие интеграции, ИИ, полнотекстовый поиск, расширение офлайна. Не включать в первый инкремент.

### Навигация — предлагаемый целевой вариант
Вкладки: Сегодня / Библиотека / Цели / Профиль. Глобальное заметное действие «Добавить» из Сегодня и Библиотеки; существующий маршрут добавления сохраняется, включая share intent/extension и ссылки приложения. Прогресс доступен из Сегодня и Целей; недельный план и повторение также имеют прямые входы. E1 сначала может добавить Сегодня, сохранив существующие маршруты и вкладки, если полная перестройка навигации рискованна. E2/E4 доводят навигацию до целевой. Не прятать старые функции без альтернативного пути.

## E1 — Сегодня: первый вертикальный срез (P0)

История: как пользователь, открыв приложение, я хочу увидеть ближайшее осмысленное действие, а не выбирать из всей библиотеки.

UI: заголовок «Сегодня», карточка ближайшего занятия, прямой вход «Пора повторить» с количеством доступных карточек, краткий недельный прогресс, быстрые действия «Добавить», «План», «Вся библиотека». В первом срезе допустимы только существующие данные: текущая недельная цель и задания; не изображать долгосрочные цели до E2. Сохранять визуальную систему (светлый фон, акцент, карточки), использовать токены и RU/EN-строки, доступные роли, динамический размер текста, safe area.

Логика: для локальной даты пользователя выбрать незавершённые задания с датой не позднее сегодня, сначала просроченные (старейшая дата), затем сегодняшние; внутри даты — приоритет по действующей модели, затем стабильный ID. Если заданий нет — ближайший запланированный материал, иначе непросмотренный (по дате добавления от старого к новому, стабильный ID). Исключить «Неактуально» и изученные из обычных рекомендаций; исключение для явного незавершённого задания по уже изученному материалу показать как отдельное занятие, не менять статус автоматически. Будущие задания не выдавать за сегодняшние. Не показывать один материал в нескольких основных блоках. В карточке показать название, источник, известную оценочную длительность, причину выбора; неизвестная длительность — «Время неизвестно». CTA открывает существующую карточку/оригинал через текущий безопасный механизм. Повторение — отдельный блок, не смешивать с изучением. Приоритет и порядок — продуктовые defaults для проверки, а не персонализация.

Данные: переиспользовать API плана, библиотеки, статистики, review. Сначала оценить объём запросов и пагинацию. Если нужен агрегат, предложить авторизованный GET /learning/today (путь адаптировать), содержащий local_date, timezone, next_action (material_id, optional task_id, reason, duration_minutes nullable), due_review_count, weekly_progress; составить контракт и тесты. Никакой новой таблицы только ради экрана. Не сканировать всю библиотеку на клиенте; серверная выборка при необходимости. Инвалидация после сохранения, завершения, переноса, смены часового пояса и повторения; обновление при фокусе/возврате. Не показывать данные прошлого аккаунта.

Состояния: загрузка без мерцания, пустая библиотека (CTA сохранить), есть материалы, но нет плана (предложить следующий), всё изучено (выбрать/добавить, не принуждать), нет карточек (нейтрально), ошибка с retry, частичный ответ, офлайн с отметкой устаревания и доступными локальными данными. Не изображать 0 при ошибке загрузки.

Приёмка:
- [ ] После входа Сегодня доступен как основной экран; старые deep links, Share, Библиотека, Добавить, Прогресс, Профиль работают.
- [ ] На тестовых данных порядок детерминирован, учитываются локальный день, статус, перенос и приоритет; неизвестное время корректно.
- [ ] Из Сегодня можно открыть материал, план, повторение, добавление и статистику; возврат обновляет данные.
- [ ] Пустые/ошибочные/офлайн-состояния и смена аккаунта проверены.
- [ ] Unit-тест выбора, API-тест авторизации/изоляции (если API менялся), компонентные тесты и ручная Android-проверка.

## E2 — долгосрочные цели и связь с материалами (P0)

История: я хочу собирать материалы не только по темам, но и по результату, которого хочу достичь. Сценарий: создать цель «Освоить Python», выбрать желаемый результат, добавить существующие материалы, запланировать один на неделю, видеть прогресс и продолжить из Сегодня.

UX: список активных/завершённых/архивных целей; экран цели с названием, необязательным описанием результата и списком материалов; кнопки добавить из библиотеки, запланировать, отметить цель завершённой, архивировать. В карточке материала — «Добавить к цели», допускается несколько целей. При отсутствии цели сохранение и обучение не блокируются. Категория/теги/коллекции сохраняются; цель отвечает на «зачем», не заменяет классификацию. Не требовать даты окончания, бюджета или приоритета при создании. Цель завершается вручную, 100% материалов не равно освоению навыка.

Модель (проект, уточнить E0): использовать существующую сущность goal, если она поддерживает долгосрочную жизнь; иначе добавить learning_goal (id, owner_id, title, description/result nullable, status active/completed/archived, timestamps) и goal_material (goal_id, material_id, position nullable, unique pair). Не дублировать существующую цель без доказанной необходимости. Много-ко-многим; проверка владельца обоих объектов на каждом запросе. Связать задания недельного плана с целью через текущие отношения либо nullable FK/таблицу соответствий. Архивирование цели сохраняет историю и материалы; отвязка не удаляет материал; удаление материала удаляет только связи или обрабатывает их согласно существующей политике. Не создавать связи с чужими ID. Старые недельные цели не терять и не объединять автоматически по имени.

Прогресс цели: число уникальных связанных материалов со статусом «Изучено» / число связанных актуальных материалов (исключить «Неактуально» из обоих). При пустом знаменателе показывать «Добавьте материалы», не 100%. Если материал в нескольких целях, отображается в каждой, но недельная общая статистика не дублируется. Ручное завершение цели независимо от процента. Явно обозначить «изучено материалов», не «освоено знаний».

API: переиспользовать существующие CRUD целей, иначе адаптировать /learning/goals, /learning/goals/{id}/materials (list/add/remove), запросы с пагинацией и подсчётом; контракты Pydantic, совместимость старых клиентов, индексы owner/status и связей, проверка повторного POST по текущим соглашениям. Миграция additive, nullable/backfill только при однозначном соответствии, тест upgrade на копии старой схемы и downgrade на тестовых данных; экспорт/импорт обновить либо явно документировать неполный охват без обещания восстановления. Не допускать тихой потери старых данных.

Приёмка:
- [ ] Создание/редактирование/архив/завершение, привязка и отвязка, повторная привязка без дубля.
- [ ] Один материал в двух целях; корректные знаменатели, пустая цель, неактуальный/удалённый материал.
- [ ] Задание из цели отображается в текущем недельном плане и Сегодня; старые задания работают.
- [ ] Изоляция двух аккаунтов, миграция старых данных, совместимость API и регрессия экспорта/импорта.

## E3 — завершение образовательного цикла (P0)

История: после внешней статьи/видео/PDF я хочу быстро отметить результат и при желании сохранить мысль, создать вопрос или выбрать следующее занятие.

UI: явный CTA «Отметить изученным» на карточке; при возврате после открытия источника — ненавязчивое «Удалось изучить?» (не чаще одного раза на сессию открытия; dismiss без изменения). При подтверждении показывать «Материал изучен» только после успешного сохранения, необязательную главную мысль, «Создать вопрос для повторения» через существующую форму и «Выбрать следующий материал», «Готово»/пропуск. Не стирать существующие заметки; использовать отдельное поле или сущность рефлексии, если переиспользование заметки приводит к потере текста. Не считать открытие доказательством изучения. Не требовать рефлексии или карточки.

Согласованность: если вход из конкретного задания, подтверждение завершает материал и это задание (не все задания по материалу); если из библиотеки без task_id, не закрывать задания молча — предложить закрыть выбранное активное задание. Предпочтительно единое серверное действие в транзакции с проверкой owner и связи задания, idempotency по существующему паттерну. Повтор запроса не создаёт дублей, не сдвигает дату первого завершения. Для старых клиентов сохранить семантику существующих ручных действий. Если транзакцию пока нельзя добавить, честно отображать частичный успех и отдельный retry; не заявлять оба изменения успешными. Снятие статуса — явное действие, не удаляет заметки/карточки и не открывает задания автоматически; статистика сохраняет текущую семантику, документировать её. Для офлайна не симулировать сохранение: если очередь поддерживает только создание ссылок/заметок, показать сетевое ограничение и сохранить ввод в безопасном черновике по текущей политике.

Приёмка:
- [ ] Изучение через библиотеку и через задание; пропуск рефлексии; сохранение мысли; карточка вопрос–ответ появляется в review по действующим правилам.
- [ ] Отказ/закрытие внешнего источника не меняет статус; повторный тап/сбой/таймаут не дублирует результат.
- [ ] Конкретное задание и материал согласованы, остальные задания не затронуты; прогресс обновлён.
- [ ] Проверены потеря сети, возврат Android, доступность, локализация, cross-account, старые маршруты.

## E4 — подбор по доступному времени и финальная навигация (P1)

История: у меня есть 5, 15, 30 или 60 минут, я хочу выбрать материал, который примерно помещается в этот интервал.

Экран/блок «Сколько у вас времени?» с четырьмя пресетами, до трёх результатов и переходом в библиотеку с соответствующим фильтром, если он реализован. Длительность нормализовать из существующего контракта (например, секунды → округление вверх до минут только при подтверждённом формате). Не путать отсутствующую оценку с нулём; исключать неизвестные из строгого подбора, показать отдельное предложение «Есть материалы без оценки времени» без обещания уложиться. Не считать оценочную длительность фактическим временем. Исключить завершённые и неактуальные. Ранжирование: активные цели, срочные задания, близость к доступному времени (дольше в пределах бюджета), старые добавления, стабильный ID. Уточнение: срочность задания имеет приоритет над целью; порядок ключей: overdue/today > active_goal > duration DESC > added_at ASC > id. Будущие задания не рекомендуются как просроченные; если включены в выбор, явно показать дату. Не вводить ИИ, сложную оптимизацию или автоматический перенос.

API при необходимости: параметры budget_minutes (5/15/30/60), limit=3, стабильный ответ с reason, duration, материалом; серверная фильтрация по владельцу и проверка пределов, индексы после анализа. Кэш с учётом пользователя, бюджета, актуальности. Пустой результат — предложить больше времени или открыть библиотеку. Не добавлять фиктивные материалы.

Навигация: Сегодня / Библиотека / Цели / Профиль; глобальное добавление и видимый переход к Прогрессу, Плану и Повторению; проверка back stack, share intent, экранов входа/восстановления, safe area и клавиатуры. Упростить карточки: важнее название, статус, источник, длительность, цель; дата и управление группами — вторично. Сохранить поиск, категории, теги, коллекции и все действия, не менять смысл старых статусов.

Приёмка: 
- [ ] 5/15/30/60 дают только подходящие известные длительности, пограничные значения и стабильная сортировка покрыты тестами.
- [ ] Нет результатов, неизвестная длительность, смена бюджета, сеть и удаление материала обработаны.
- [ ] Добавление доступно с основных экранов и через ОС, старые deep links и прогресс работают.

## E5 — аналитика, QA, выпуск (P0 для внешнего пилота)

События (названия согласовать с app/metrics.py): registration_completed, material_saved, today_viewed, next_action_opened, saved_material_reopened, material_studied, goal_created, goal_material_linked, study_reflection_saved, review_card_created, review_completed, time_budget_selected, recommendation_opened. Событие успеха только после подтверждения соответствующего действия; избегать повторов при retry. Не отправлять URL, заголовки, тексты заметок, ответы карточек, PDF, email или токены; минимальные технические параметры, owner pseudonym только по политике. Не внедрять внешнюю аналитику без решения владельца. Различать события клиента и серверный факт статуса.

Метрики: Weekly Active Learners = уникальные аккаунты с первым успешным переходом ранее сохранённого материала в «Изучено» за локальную календарную неделю (не повторный тап). Активация = доля новых пользователей, сохранивших и изучивших хотя бы один материал в 7 дней; отдельно первый возврат в другой сессии. Save-to-study 7d = доля сохранённых материалов когорты, впервые изученных в 7 дней от сохранения. D7/D30 — возвращение к продукту в соответствующий день от регистрации; отдельно learning retention. Измерять время до первого изучения, долю начатых рекомендаций, создание целей и повторение. Все знаменатели/окна задокументировать; целевые значения после baseline, не выдумывать результаты.

Регрессия: авторизация/письма, share (ссылка и текст до/после входа), очередь и дубль, библиотека и фильтры, PDF с существующими лимитами и проверкой, заметки, статусы, план/перенос/длительность, карточки/пауза/история, уведомления, импорт/экспорт, смена языка/часового пояса/аккаунта, удаление аккаунта, офлайн. Тесты API: 401/403/404 по действующему контракту, невозможность доступа к чужим объектам, idempotency, транзакции, pagination, ошибки, миграция. Клиент: типизация/линт/тесты согласно репозиторию; ручные проверки Android физически, iOS если доступно. Уведомления и SMTP не считать готовыми без сквозной проверки; миграция длительности на стенде не подтверждена. Проверить релизный чек-лист, секреты/логи, резервное копирование БД и PDF. Не публиковать автоматически.

Критерии выпуска: все P0 закрыты, P1 либо закрыты, либо явно вынесены в следующий релиз; нет критических регрессий/утечки данных; тестовый upgrade подтверждён; инструкции отката/выключения новой навигации и совместимости зафиксированы. Предпочесть локальный feature flag/конфигурацию, если уже существует; не строить отдельную платформу флагов. В пилоте 5–8 UX-сеансов, затем 2–4 недели использования небольшой группой (ориентир, не обещание сроков разработки). Проверить: находят ли следующий шаг, связывают ли материалы с целью, возвращаются ли, используют ли подбор. Не расширять продукт до проверки базового цикла.

## Общая Definition of Done

- [ ] Требования и критерии этапа сопоставлены с фактическим кодом; новый код следует архитектуре и дизайну проекта.
- [ ] Нет удаления существующих возможностей, потери данных, регрессии API, смешивания аккаунтов, новых секретов.
- [ ] RU/EN, accessibility, loading/empty/error/offline, сеть/повтор запроса, стабильные состояния, безопасные внешние ссылки.
- [ ] Автотесты и результаты команд зафиксированы; ручные проверки отмечены отдельно; непроверенное не названо готовым.
- [ ] Обновлены документация/API/миграции/чек-листы, сформирован краткий отчёт и список открытых вопросов.

## Не входит в объём

ИИ-конспекты и карточки, семантический поиск, полноценный встроенный ридер, полная офлайн-синхронизация, социальные функции, подписка, маркетплейс. Сохраняются текущие ограничения PDF/импорта/офлайна до отдельных решений. Предлагаемый интерфейс не требует новой дизайн-системы. Пользовательские гипотезы подтверждать пилотом, а не количеством реализованных функций.

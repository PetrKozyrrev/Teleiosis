# API (FastAPI)

Интерактивная документация при запущенном сервере: http://127.0.0.1:8000/docs
(на боевом сервере /docs и /openapi.json закрыть).

Состояние на 08.11.2026: API готов для библиотеки (материалы, категории). Клиент (сайт) ещё не написан. Регистрации и входа для сайта пока нет: токен сессии выдаёт только замороженный вход по Telegram. Планируемые эндпоинты перечислены в конце файла.

## Авторизация
Пользователь определяется зависимостью `get_current_user` (app/deps.py). Способов входа два:
1. **Токен сессии:** заголовок `Authorization: Bearer <токен>`. Сейчас токен выдаёт только POST /auth/telegram (заморожен). Срок 24 часа без продления, до 10 сессий на пользователя. В БД хранится только SHA-256-хэш токена. Формат токена проверяется до обращения к БД (A-Z, a-z, 0-9, _ и -, длина 16-128). Для сайта способ получения сессии будет выбран на этапе 6.
2. **Бот (заморожен):** заголовки `X-Bot-Key` (секрет, не короче 32 символов, иначе вход ботом отключён) + `X-Telegram-Id` + необязательно `X-Telegram-Username`. Пользователь создаётся при первом запросе.

Если передан `Authorization`, это единственный способ входа; вместе с `X-Bot-Key` он даёт 401. Любая неудача входа даёт 401 без перехода к другому способу.

## Ошибки
| Код | Когда |
|---|---|
| 401 | Нет данных входа, они неверные, сессия просрочена или удалена; одновременно переданы Authorization и X-Bot-Key |
| 404 | Чужой или несуществующий ресурс (не 403: чужие данные не раскрываем) |
| 409 | Дубль: категория с таким названием или материал с такой ссылкой уже есть |
| 422 | Некорректные данные запроса (см. также ниже) |
| 503 | Вход по Telegram недоступен: на сервере не задан BOT_TOKEN |

Проверка формата заголовков идёт до проверки входа, поэтому слишком длинный `Authorization` (больше 512 символов), `X-Bot-Key` (больше 256), `X-Telegram-Username` (больше 64) или некорректный `X-Telegram-Id` (не число, ноль, отрицательное, больше BIGINT) дают 422, а не 401. Идентификаторы в адресе вне диапазона BIGINT тоже дают 422.

## Эндпоинты
| Метод и путь | Назначение | Ответы |
|---|---|---|
| GET /health | Проверка работы, без авторизации | 200 |
| GET /me | Текущий пользователь (при входе ботом создаётся при первом обращении) | 200, 401, 422 |
| POST /categories | Создать категорию `{name}` (1-50 символов после обрезки пробелов) | 201, 401, 409, 422 |
| GET /categories | Список своих категорий по алфавиту | 200, 401 |
| PATCH /categories/{id} | Переименовать `{name}` | 200, 401, 404, 409, 422 |
| DELETE /categories/{id} | Удалить; материалы остаются без категории | 204, 401, 404, 422 |
| POST /contents | Сохранить материал `{url?, note?, title?, category_id?}`; нужен url или note | 201, 401, 404 чужая категория, 409 дубль, 422 |
| GET /contents | Список материалов (параметры ниже) | 200, 401, 422 |
| GET /contents/{id} | Один материал | 200, 401, 404, 422 |
| PATCH /contents/{id} | Изменить только `title`, `note`, `status`, `category_id` | 200, 401, 404, 422 |
| DELETE /contents/{id} | Удалить материал (напоминания удаляются каскадом) | 204, 401, 404, 422 |
| POST /auth/telegram | Заморожен. Обмен initData на токен сессии: `{init_data}` → `{token, token_type, expires_at, user}`; ответ с `Cache-Control: no-store` | 200, 401 любая ошибка проверки, 422, 503 |
| POST /auth/register | Регистрация на сайте: `{email, password, consent}` → 201 `UserOut`. Сессию пока не выдаёт (вход в подшаге 6.3) | 201, 409 e-mail занят, 422 |

## Поля ответов
- **Пользователь (UserOut):** `id`, `telegram_id` (для пользователей сайта `null`), `email` (для пользователей из Telegram `null`), `username`, `timezone`. Поля настроек напоминаний (`reminders_enabled`, `reminder_time`) в ответ пока не входят.
- **Категория:** `id`, `name`, `created_at`.
- **Материал (ContentOut):** `id`, `category_id`, `title`, `url`, `description`, `note`, `content_type`, `source`, `image_url`, `status`, `studied_at`, `created_at`, `updated_at`.

## POST /contents
- Принимаются только http и https, длина до 2048 символов, без пробелов, хост с точкой, без логина и пароля в ссылке. Адрес без схемы получает `https://`. Недопустимая ссылка даёт 422.
- Ссылка нормализуется для поиска дублей: https, без www, без трекинговых параметров и фрагмента `#`; YouTube приводится к `youtube.com/watch?v=ID`; `t.me` без параметров.
- Дубль среди материалов пользователя: 409 с телом `{"detail": {"message": "Already saved", "existing_id": N}}`.
- Название: из запроса (до 300 символов), иначе загруженное со страницы, иначе временное (адрес без https:// или первая строка заметки). Заметка до 10 000 символов.
- Загрузка метаданных best-effort (до ~6 секунд, при любой ошибке сохраняется ссылка), с защитой от SSRF (app/metadata.py); YouTube через oEmbed. Для заметок без ссылки метаданные не загружаются.
- Источник и тип определяются по адресу: youtube/video, telegram/post, web/article; заметка: other/note.

## GET /contents: параметры
`q` (поиск по названию, до 100 символов), `status` (unseen, planned, studied, irrelevant), `source` (youtube, telegram, web, other), `category_id`, `uncategorized` (true), `sort` (newest, oldest, title), `limit` (1-100, по умолчанию 20), `offset` (до 1 000 000).
`category_id` вместе с `uncategorized` даёт 422. К любой сортировке добавляется id для стабильного порядка.
Ответ: `{items, total, limit, offset}`.

## PATCH /contents/{id}
- Меняются только `title`, `note`, `status`, `category_id`; лишние поля (в том числе `url`, `user_id`) дают 422. Пустое тело даёт 422.
- `title` и `status` не могут быть null. `title` от 1 до 300 символов.
- `category_id: null` снимает категорию; чужая или несуществующая категория даёт 404 (и ничего не меняется).
- `note`: пустая строка или null удаляют заметку, но у материала без ссылки заметку удалить нельзя (422).

## Статусы
Один статус на материал, переходы свободные. `studied_at` ставится при входе в `studied` и очищается при выходе.

## POST /auth/register
- `email` проверяется и приводится к нижнему регистру (так же будет работать вход); некорректный адрес даёт 422. DNS-проверка адреса не выполняется.
- `password`: от 10 до 128 символов, без требований к составу, не обрезается. В БД хранится только хэш Argon2id.
- `consent` должен быть `true`, иначе 422. Сохраняются `consent_at` и `consent_version` (пока `draft-1`, заменить версией текста от юриста).
- Занятый e-mail (без учёта регистра): 409 `{"detail": "Email already registered"}`. Принятый компромисс: ответ позволяет узнать, что адрес зарегистрирован; закрывается ограничением частоты (подшаг 6.4).
- Лишние поля дают 422. Ответ с `Cache-Control: no-store`.

# Приёмка мобильного блока 2

Блок начат по явному сообщению пользователя «Давай переходить к мобильной разработке». Публичный HTTPS/SMTP и полная приёмка серверного блока 1 остаются открытыми; переход разрешён пользователем, а не означает их завершение. Каркас 0.1 работал без сервера. В 0.2 добавлены auth/API: приватная проверка готова, публичная и device-приёмка открыты.

## Ресурсы

- Есть физический **Samsung S25**, пользователь может подключить его по USB. Версия Android и фактическая доступность ADB пока неизвестны.
- Аккаунтов магазинов пока нет. Mac/macOS CI и физический iPhone не подтверждены.
- Android без Google-сервисов: требование не подтверждено; каркас не включает GMS/FCM. Нужны отдельное устройство и выбранный push-дистрибьютор для проверки покрытия.
- Linux/WSL2: можно генерировать оба нативных проекта, собирать Android. Xcode/подпись/iOS runtime здесь недоступны.

## Протокол устройства

Инструкция установки/сценарии/ADB: [mobile/README.md](../mobile/README.md). Для каждого прогона записать модель/ОС, идентификатор и SHA-256 APK, способ установки, результат по строкам матрицы, шаги воспроизведения ошибок. Только синтетические ссылки/текст; без токенов, паролей и личных заметок. Удаление приложения и смена подписи не выполняются автоматически.

## Дополнение: блок 3 / APK 0.2.0

Контракт и полный отчёт: [mobile_auth.md](mobile_auth.md). Backend764 tests, mobile64 tests, TS/lint, Alembic и private HTTPS auth smoke проходят. APK0.2/code2 готов, API/worker/privateproxy обновлены; публичные80/443 не включены.

После согласованного публичного HTTPS-запуска и получения пароля шлюза через доверенную консоль:

1. Обновить APK без удаления приложения (подпись совпадает). «Настройки → Аккаунт → Доступ к тестовому стенду»: ввести отдельный gateway-пароль.
2. Зарегистрировать синтетический e-mail с тестовым consent, выйти, войти; неверный пароль не раскрывает наличие аккаунта.
3. Закрыть/перезапустить приложение: профиль восстановится только после server check. При отсутствии сети token не должен теряться; проверить возврат сети.
4. Проверить вход в тот же аккаунт на сайте. Cookie/Bearer транспорт API проверен автоматически; сайт не переписывался.
5. Запросить verification/reset: оператор читает только своё тестовое письмо через scripts/captured_mail.py. Полную HTTPS-ссылку можно вставить в «Открыть ссылку из письма». Проверить успех/просроченную/повторную ссылку.
6. После reset проверить отзыв mobile и web сессий. Выйти с телефона, перезапустить: прежний профиль не восстанавливается. Offline logout проверять только через явную кнопку локального выхода, с пониманием неподтверждённого server revoke.
7. Verified Android App Link/cold+warm/fragment, reinstall/Keychain на iOS и реальный SecureStore failure остаются отдельными пунктами, не заменяются ручной вставкой ссылки или mocks.

Ссылки и пароли не присылать в чат/логи. Результаты фиксировать с моделью/ОС/версией APK; сценарии не отмечены пройденными заранее.

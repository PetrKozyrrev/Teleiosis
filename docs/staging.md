## Что изменилось

APP_ENV=staging сохраняет HTTPS, Secure/HttpOnly cookie, секрет подписи и закрытые docs/redoc/OpenAPI. EMAIL_BACKEND=capture допустим только в staging; APP_ENV=prod по-прежнему требует SMTP и TLS. Console не допускается ни в staging, ни в prod. Production-настройки не ослабляются.

Перехват — стандартные MIME `.eml` в отдельном Docker volume `capture_mail`, подключённом только к API/worker. Каталог 0700 принадлежит uid 10001, файлы 0600, запись атомарная. SMTP-соединения не создаются, тела и токены не выводятся в логи. Максимум 1000 писем; при заполнении отправка возвращает false с ошибкой в логах, старые письма не удаляются молча. Частичные файлы при ошибке записи удаляются. Параллельные процессы могут незначительно превысить этот мягкий лимит; это не дисковая квота.

Никакого публичного UI/API почтового перехватчика нет. Оператор читает письма только через SSH. Письма всех тестовых аккаунтов доступны оператору: использовать исключительно синтетические данные, не настоящие пользовательские библиотеки и пароли от других сервисов. Перехват проверяет генерацию писем и ссылки, а не попадание в реальный ящик, SPF/DKIM/DMARC, блокировки SMTP или спам-фильтры.

Из доверенной SSH/веб-консоли сервера:

```sh
python3 /srv/teleiosis/scripts/captured_mail.py
python3 /srv/teleiosis/scripts/captured_mail.py 0123456789abcdef0123456789abcdef.eml
```

Вторая команда — пример: подставить имя из списка. Вывод содержит одноразовые ссылки; его не копировать в чат, issues или общие логи. Подтверждение e-mail/сброс на этом этапе проверяет оператор, а не доставка тестеру.

Воркер при этом считает успешный capture отправкой выбранного тестового транспорта. Не интерпретировать `sent` как внешнюю доставку. По окончании теста оператор отдельно удаляет его захваченные письма; основной экспорт/удаление аккаунта не управляет файловым staging-архивом. Автоматической ротации по времени пока нет. Перед внешними пользовательскими данными этот режим непригоден без отдельного решения о данных/сроках и замены реальным SMTP.

## Конфигурация

Базовый deploy/compose.yml остаётся конфигурацией production по умолчанию. Явный `TELEIOSIS_STAGING=1` подключает deploy/compose.staging.yml. Overlay принудительно задаёт staging/capture для migrate/API/worker и добавляет закрытый почтовый том; обычный `up` не включает proxy, поскольку у него профиль public.

```sh
export TELEIOSIS_STAGING=1
sh deploy/compose.sh config --quiet
sh deploy/compose.sh up -d --wait db
sh deploy/compose.sh run --rm migrate
sh deploy/compose.sh up -d --wait api worker
```

`deploy/.env.staging.example` содержит поля, но не секреты. На действующем сервере уникальные пароли/SECRET_KEY/gateway hash созданы только на сервере, deploy/.env имеет 0600. Не перезаписывать этот файл новым примером и не выводить `compose config` без --quiet. Wrapper не выполняет env-файл как shell-код. Переменная TELEIOSIS_STAGING задаётся окружением команды явно.

Одноразовый mail-init делает mount доступным только uid 10001; root и CHOWN/FOWNER есть только у этого init, у API/worker права не повышаются. Данные БД и почты в разных томах. Существующую рабочую БД MVP на стенд не переносили.

## Egress на текущем сервере

Для Docker iptables-nft используется deploy/egress-iptables.sh, не исторический native-nft пример. Управляются только TELEIOSIS-EGRESS/PRIVATE/HOST и их hooks DOCKER-USER/INPUT; глобальные host-политики и SSH не меняются. Фильтрация bridge включена через br_netfilter. Разрешён PostgreSQL 172.30.61.2:5432, private/metadata-сети и новые соединения приложения с хостом запрещены; публичный HTTPS и ответы установленным соединениям сохраняются.

teleiosis-egress.service применяется перед Docker, Docker drop-in требует успешный сервис до старта контейнеров. После изменения подсетей/статических IP правила нужно пересмотреть согласованно. Script `apply` отказывается молча заменять частично изменённые правила, `check` проверяет ожидаемые правила. Предыдущий iptables-save сохранён на сервере в /var/lib/teleiosis/iptables-before-staging.v4; не восстанавливать весь старый ruleset поверх работающих контейнеров без плана. Для отката только этих правил сначала остановить контейнеры Teleiosis, убрать Docker drop-in/автозапуск сервиса, затем удалить только hooks/цепочки TELEIOSIS-*; чужие правила не очищать.

Подтверждено реальными соединениями: API → БД и публичный HTTPS проходят; API → собственный private probe в той же bridge-сети и API → host SSH отклоняются. Счётчики соответствующих правил увеличились. К реальному cloud metadata endpoint не обращались. IPv6 в сетях приложения не включён. SSH/предустановленный мониторинг Timeweb продолжают работать.

# Подблок 9Б — импорт и расширенный поиск

21.11.2026 пользователь принял локальный результат 9Б и разрешил 9В. Отдельная приёмка устройств и развёртывание стенда остаются открыты. [Подблок 9В](mobile_pdf.md).

## Контракт до реализации — 21.11.2026

Импорт принимает один UTF-8 JSON собственного экспорта Teleiosis версии 1 (включая ранние выгрузки без тегов, коллекций и назначений). Пределы на запрос: 2 МиБ, 500 материалов, 200 категорий, 200 тегов, 200 коллекций и 20 назначений каждого вида на материал. В аккаунте остаётся квота по 200 тегов и коллекций. Названия групп и категорий — до 50 символов, названия материалов — до 300, заметки и описания — до 10 000, HTTP(S)-ссылки — до 2048. CSV, произвольные форматы и двоичные вложения вне 9Б.

- `POST /mobile/library/imports/preview` и `POST /mobile/library/imports/apply` принимают исходный JSON как `application/json`. Предпросмотр показывает количество новых и повторных материалов, новых категорий, тегов, коллекций и назначений. На сервере он только читает данные. Запись требует отдельного действия в приложении. Сервер повторяет проверку и рассчитывает итог на текущих данных, поэтому итоговые числа могут отличаться от предпросмотра при параллельном редактировании.
- Повреждённый документ, неподдерживаемая версия, повтор идентификатора, ссылка на отсутствующий объект, недопустимые поля материала или выход за структурный лимит отклоняют весь импорт, с кодом и местом ошибки без содержимого файла. Ответы: 413 — размер файла, 415 — тип запроса, 422 — формат или данные, 409 — квота назначения или конфликт записи, 401 — сессия. Приложение предлагает повторить проверку после исправления файла или восстановить подключение/вход.
- Идентификаторы из файла используются только для связей внутри документа. Категории подбираются по имени без учёта регистра, теги и коллекции — по виду и имени без учёта регистра, в текущем аккаунте. Создаются отсутствующие категории и группы, включая пустые. У новых материалов сохраняются назначения, локальные поля материала, статус и даты/счётчик из выгрузки. Источник определяется по ссылке. Импорт не загружает метаданные и не переносит профиль, историю активности, напоминания, токены или владельца.
- Дубли ссылок определяются по существующей нормализации URL. Для заметок без ссылки используется точная пара «название, текст». Существующие материалы пропускаются целиком вместе с их импортируемыми назначениями. Для дублей внутри файла берётся первая запись. Применение атомарно, включая назначения и квитанцию по SHA-256 файла и аккаунту. Повтор тех же байтов возвращает первоначальную квитанцию, в том числе после потери ответа. Переформатированный файл проверяется заново по правилам дублей. Импорт работает онлайн и не попадает в очередь submissions.
- Расширенный режим через `GET /mobile/library/search` принимает те же фильтры и параметры страницы, что `GET /contents`. `search_in` задаёт область `all`, `title`, `note`, `description` или `url`. Поиск — буквальная подстрока без учёта регистра, запрос до 100 символов. `all` означает совпадение в любом из четырёх полей; фильтры статуса, источника, категории, тега и коллекции соединяются через AND. Сортировка и ограничения страниц прежние. Поиск ограничен сохранёнными полями; текст удалённых страниц, PDF и вложений недоступен. Расширенный режим работает онлайн. Обычный поиск по названию, его офлайн-режим и параметры старых клиентов сохраняются.
- Новые маршруты используют существующий шлюз `/mobile/*`. Проверка учётных данных остаётся общей для Bearer и cookie/CSRF. Сайт и APK 0.6.0 сохраняют прежние маршруты и формат очереди.

## Реализация и подготовка к приёмке

- В приложении откройте «Настройки аккаунта и данные» → «Импортировать выгрузку». Действия «Выбрать файл», «Проверить файл» и «Импортировать» идут отдельно. В библиотеке откройте «Фильтры и сортировка» → «Искать в». Обычный поиск остаётся режимом по умолчанию. Расширенный режим перезапускает пагинацию при изменении запроса, поля или фильтров.
- APK **0.7.0/code13** · [APK](../mobile/artifacts/teleiosis-0.7.0-android-arm64-preview.apk) · [отчёт проверяющего скрипта](../mobile/artifacts/teleiosis-0.7.0-android-arm64-preview.apk.report.json). 32 169 952 байта, SHA-256 `d32339d41db0670d5e75e298d5812f4b20f56524be5004ebb6e2d23ce2a21530`. Подпись v2 и закреплённый сертификат подтверждены, arm64, 25 ELF-библиотек, выравнивание ZIP/ELF 16 КиБ. Сверка SHA-256 с отчётом выполнена отдельно.
- Локальный образ `teleiosis:import-search-20261121`, `linux/amd64`, ID `sha256:6e1bec21d69309eb5a5f8a3eb70970156abe6d977ac2ca0649f2a987b31497cf`. Alembic `p6e8f0a2b4c5` добавляет только таблицу квитанций `library_imports` поверх `n5d7e9f1a3b4`. В квитанции хранятся SHA-256 исходных байтов и счётчики, с каскадным удалением при удалении аккаунта.
- Временная копия системного выбора удаляется после чтения, приложение держит байты в памяти до завершения операции или ухода с экрана. Системный поставщик Android/iOS может копировать файл до того, как приложение проверит размер. Лимит проверяется перед чтением, а API ограничивает размер во время получения. Расширенный поиск не записывает результаты в офлайн-кэш. Простой поиск, существующий формат SQLite и очередь остаются совместимыми с 0.6.0.
- Сборка подключается к закрытому стенду. Пока там работает API 9А, старые сценарии доступны, а 9Б показывает, что серверный маршрут ещё недоступен. Процедура установки поверх 0.6.0 и новые функции требуют ручной приёмки.

## План обновления стенда после отдельного согласования

1. Сверить ревизию, образ API и контейнеры из отчёта 9А. Сохранить прежний API-образ и приватный снимок конфигурации. Создать новый архив через `deploy/backup.sh` в каталоге с правами 0700. Прогнать `deploy/restore-check.sh` в новой временной БД и сверить ревизию и количество строк, включая категории, группы и назначения.
2. Загрузить проверенный образ и сверить ID. Закрепить его через `TELEIOSIS_API_IMAGE` для API/migrate и отдельно проверить итоговый Compose. Применить `p6e8f0a2b4c5` одноразовым migrate и обновить только API. Сервисы worker, БД и Caddy исключить из пересоздания. Push оставить выключенным.
3. Проверить healthy, ревизию и публичный HTTPS на двух вымышленных аккаунтах. Проверить разделение Basic/Bearer, веб-cookie/CSRF, старую библиотеку, предпросмотр, импорт, повтор, поиск и отсутствие перекрёстного доступа. Удалить тестовые аккаунты и данные.
4. При откате вернуть прежний pin API и перезапустить только API. Добавочную таблицу и новые материалы сохранить. Downgrade удаляет квитанции, включая подтверждение уже применённых файлов, поэтому его можно рассматривать отдельно после остановки записи и свежего подтверждённого backup. Восстановление архива с заменой рабочей БД требует отдельного решения и сверки записей, сделанных после снимка.

## Ручная проверка

- **S25 (Android 17 / One UI 9.0).** Установить 0.7.0 поверх 0.6.0. Проверить вход, локальный кэш, очередь и «Поделиться». Выбрать файл из системного приложения «Мои файлы», отменить выбор, проверить валидную и повреждённую выгрузку, слишком большой файл, повтор после применения и после прерывания сети. Проверить категории, теги, коллекции и назначения новых записей с двумя тестовыми аккаунтами. Проверить поля поиска, комбинированные фильтры, переход на следующую страницу, смену запроса и восстановление связи. Старый поиск должен находить загруженные данные без сети.
- **iOS.** На Mac/Xcode собрать подписанный кандидат. На iPhone проверить приложение «Файлы», временную копию, импорт, повторы и поиск, смену сессии, переходы между фоном и активным состоянием, share extension и установленную ранее платформенную матрицу. Проверки на устройстве открыты.
- Реальная доставка RuStore/APNs, SMTP, остальные проверки App Links, публикация и общий пилот относятся к открытым платформенным и релизным задачам.

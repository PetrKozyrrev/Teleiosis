# Первый бесплатный релиз — порядок подготовки

Актуально на 23.11.2026. Пользователь принял карточки и повторение на S25 в APK 0.10.0/code17 и выбрал первый бесплатный релиз. ИИ отложен до периода после релиза. Рабочий вариант первого канала — Android/RuStore, ранее выбранный пользователем. Срок и состав iOS-выпуска требуют отдельного решения.

## 1. Создать кабинет RuStore

Владелец проекта входит в RuStore Консоль через VK ID и регистрирует аккаунт разработчика с подходящим фактическим статусом. Для бесплатного приложения доступна регистрация физического лица. Выбор ИП или юридического лица зависит от владельца продукта. Перед будущей монетизацией условия выбранного статуса следует проверить повторно. Регистрация в консоли бесплатна. [Инструкция RuStore](https://www.rustore.ru/help/developers/developer-account/registration-developer).

Результат для продолжения — сообщение «Кабинет готов, статус …», выбранное публичное имя разработчика и адрес поддержки. Если кабинет уже существует, использовать его. Логин и пароль VK ID остаются у владельца.

## 2. Определить адрес приложения и отправителя писем

Владелец выбирает постоянный домен или подтверждает имеющийся адрес для публичного использования. Дополнительный домен приобретается только после решения о расходах. Вместе с этим выбрать адрес поддержки и адрес отправителя служебных писем.

Я подготовлю HTTPS, адреса API и переходы восстановления пароля/подтверждения почты для релизной сборки. Переключение действующего стенда и отдельная среда требуют конкретного согласования после подготовки плана. Текущий закрытый стенд использует отдельный пароль шлюза и перехватывает письма администратором. Для пользователей магазина нужно подготовить публичную среду с реальной доставкой писем.

Результат — выбранный hostname, контакт поддержки и решение о том, какая среда обслуживает публичное приложение.

## 3. Подготовить SMTP

Сначала проверить возможности уже имеющейся почты или хостинга. Если отправка через SMTP доступна, получить у провайдера адрес сервера, порт, способ TLS, логин, адрес отправителя и отдельный пароль приложения. DNS-записи для отправки настроить по инструкции выбранного провайдера. Платный почтовый сервис подключать после согласования стоимости.

В чат достаточно передать название провайдера, host, port, тип TLS и адрес отправителя. Пароль передаётся через согласованное приватное размещение на сервере. Я настрою окружение и проверю получение писем регистрации, подтверждения и восстановления на реальном почтовом ящике, срок действия ссылок и возврат в приложение.

Результат — письмо дошло получателю, ссылка корректно обработана, секреты отсутствуют в репозитории и APK.

## 4. Зафиксировать идентичность и подпись Android

Если постоянный ключ подписи уже есть, сообщить это и указать безопасное место его хранения. Если ключа нет, сообщить «Постоянного ключа нет». Затем я подготовлю процедуру создания и резервирования ключа, согласуем постоянный package ID и соберём магазинный артефакт. Имя приложения сейчас содержит пометку «тест», package ID — ru.teleiosis.mobile.dev, сертификат — тестовый ключ шаблона.

Приватный keystore и пароли хранить в защищённом месте, сделать независимую резервную копию. В документации фиксировать публичный отпечаток сертификата. Перед первым выпуском проверить план обновлений и перенос нужных тестовых данных. Для обновлений Android важна согласованная подпись. [Работа с подписями в RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/apk-signature).

Результат — согласованы постоянный package ID, ключ и место резервной копии, собран и проверен APK для магазина.

## 5. Подготовить сведения о владельце и документы

Владелец определяет, от чьего имени работает сервис, публичные контакты и порядок обращений пользователей. На этой основе готовятся политика конфиденциальности, пользовательские условия и окончательное согласие. Их содержание должно соответствовать фактической обработке данных. Я могу подготовить техническое описание данных и подключить утверждённые тексты и ссылки в приложение и сайт. В текущем приложении используется тестовое согласие draft-1.

RuStore требует политику конфиденциальности для приложений, обрабатывающих персональные данные. Тексты следует проверить с подходящим специалистом с учётом конкретного владельца и устройства сервиса. [Требования RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps).

Результат — действующие публичные URL документов и согласованный текст регистрации.

## 6. Зафиксировать состав бесплатного выпуска

Подтверждённые функции — библиотека, организация и поиск, импорт/экспорт, PDF, недельный план и ручное повторение. Публичное описание и квоты должны соответствовать подготовленной серверной конфигурации. Бесплатный выпуск использует технические ограничения для защиты ресурсов. Подписка и цены из старого pricing.md остаются гипотезами до отдельного решения.

Нужно выбрать выпуск с включённым push после реализации и проверки либо с отключённым push и точным описанием доступных напоминаний. Сейчас RuStore SDK в клиенте отсутствует, push выключен, APNs открыт. Список повторений внутри приложения уже работает.

PDF сейчас хранится на диске сервера с квотой. Код разрешает этот режим для тестовой среды и отвергает его при APP_ENV=prod. До публичного запуска я должен подготовить и проверить выбранный вариант хранения и восстановления. Для сохранения текущих расходов можно доработать режим приватного диска на существующем сервере. S3 обсуждается при отдельном решении о расходах. Ограничение нынешнего кода само по себе не требует покупать хранилище.

Результат — согласованы функции, квоты, каналы напоминаний и способ публичного хранения PDF.

## 7. Подготовить карточку магазина и финальную проверку

Я подготовлю описание по работающим функциям, список изменений, скриншоты и проверку релизного APK. Владелец утверждает название, описание, контакты и материалы магазина. Форматы и обязательные поля сверяются с актуальной RuStore Консолью. [Порядок публикации RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication).

Перед передачей на модерацию проверить магазинную сборку на S25, вход/выход, реальные письма, восстановление, библиотеку и PDF, офлайн-очередь, план, карточки, экспорт и удаление аккаунта. Для будущего iOS-выпуска нужны Mac/Xcode, подпись и физический iPhone. Проверки ранее принятых тестовых APK сохраняются, а окончательная сборка проходит собственную приёмку.

Результат — проверенный подписанный артефакт с SHA-256, утверждённая карточка магазина и отчёт с открытыми ограничениями.

## 8. Отдельно разрешить модерацию и публикацию

После подготовки результата владелец согласует загрузку артефакта, отправку на модерацию и публикацию. Настройки момента выпуска следует проверить перед отправкой. При замечаниях магазина исправить конкретные пункты, повторить нужные проверки и согласовать дальнейший выпуск.

## С чего начать сейчас

Достаточно подготовить кабинет RuStore и сообщить его статус, выбранный домен, адрес поддержки, доступного почтового провайдера и наличие постоянного ключа подписи. Можно отвечать по мере готовности. Пароли, токены, keystore и рабочие .env в чат и Git не передавать.

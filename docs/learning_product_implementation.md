## E8. Цели и недельное расписание

Карточка цели открывается целиком, содержит ожидаемый результат и прогресс по материалам. В деталях показан ближайший актуальный материал цели. Редактирование, ручное завершение и архивирование остались в нижнем блоке. Прогресс в 100% относится к материалам, статус цели меняется вручную.

Множественный выбор открывается отдельным экраном. API выдаёт ограниченную страницу поиска по названию и помечает уже связанные материалы. Отмеченные позиции сохраняются при переключении страниц. Клиент последовательно вызывает прежнее добавление связи, показывает подтверждённые результаты и оставляет неподтверждённые позиции для повтора. При потере сети или сессии серия останавливается. Новый read-only маршрут и поле в деталях расширяют прежний API без миграции.

Старые недельные и долгосрочные цели используют `StudyGoal`. В интерфейсе создание идёт через вкладку «Цели», исторические задания и публичные маршруты плана сохраняются. Расписание показывает календарную неделю, оценки минут и число завершённых заданий, группирует задачи по дню аккаунта и выделяет сегодняшние. Бюджет свёрнут по умолчанию. Перенос использует локализованный выбор даты по неделям, отправляет прежний ISO-день с версией задания и сохраняет статус материала. Завершение задачи требует подтверждения, после которого учитывается только задача в плане.

Для ручной приёмки нужен тестовый API с маршрутом E8. На старом API клиент показывает сообщение о недоступности множественного выбора. [Чек-лист](mobile_testing.md#e8-цели-и-недельный-план)

Изменены `app/routers/learning_goals.py`, `mobile/src/learning/goals.tsx`, `mobile/src/app/{_layout,plan}.tsx`, маршрут `mobile/src/app/goals/materials.tsx`, `mobile/src/plan/{model.ts,DatePicker.tsx}`, общий `Card`, тип маршрута API и словарь EN. Проверки дополнены в `tests/test_learning_goals.py` и `mobile/tests/{goalsScreen,weekPlan,learningRoutes}.test.tsx`.

## E9. Повторение, завершение и быстрый захват

База E9 — `e7dc449`, APK 0.17.0/code25. Владелец подтвердил успешную проверку E8 и разрешил продолжить.

Карточка «Не помню» остаётся доступной по текущему алгоритму и может попасть в следующий добровольный раунд. После оценки клиент ждёт подтверждённый ответ. Повтор после сетевого сбоя использует ту же оценку, версию и ключ операции. Конфликт версии можно пропустить без записи. Итог считает подтверждённые ответы и запрашивает у сервера актуальный остаток. ## E1. Решения

- Добавляем авторизованный read-only `GET /mobile/learning/today` с локальной датой и зоной, одним занятием, доступными карточками и недельным прогрессом. API плана ограничен одной неделей, а вычисление на клиенте потребовало бы обхода истории и библиотечных страниц. Используем серверные выборки с фильтрацией по владельцу и ограничением выдачи. Таблицы, версии записей и прежние ответы API сохраняются.
- Незавершённые задания до сегодня включительно упорядочены по дате, приоритету и ID. Явное задание по изученному материалу имеет отдельную причину. Если подходящего задания нет, сначала берём материал со статусом `planned`, затем `unseen`, по дате добавления и ID. Открытые будущие задания резервируют материал для своей даты. Статус `irrelevant` исключён из выдачи. Отдельные признаки позволяют различить пустую библиотеку, отложенное обучение и отсутствие актуальных материалов для рекомендации.
- Длительность задания берём из его оценки. Для материалов без задания берём длительность видео, округлённую вверх до минуты, или текущую оценку чтения. При отсутствии обоих значений показываем «Время неизвестно».
- Главный маршрут `/` открывает «Сегодня». Библиотека остаётся отдельной вкладкой на `/library`. Ссылки деталей `/library/[id]`, добавления, прогресса, профиля, входящих материалов, плана, повторения и действий из писем сохраняют пути. Внутренние переходы с назначением «Библиотека» обновляются.
- Один снимок экрана сохраняется в SQLite-кэш с ключом владельца. Обновление на фокусе перечитывает данные после сохранения, завершения, переноса, изменения пояса или ответа на карточку. Возврат приложения на передний план и синхронизация очереди тоже запускают запрос. При сетевой ошибке или 5xx показываем собственный снимок с отметкой устаревания. Без снимка остаются навигация и retry, а недоступные показатели не подменяются нулями. Карточка материала в офлайне использует уже скачанные детали или страницы библиотеки. План, ответы на карточки и получение PDF сохраняют прежние требования к сети.

## E5. Внутренняя аналитика и подготовка пилота

### События и данные

- Сервер пишет подтверждённые факты `registration_completed`, `material_saved`, `material_studied`, `goal_created`, `goal_material_linked`, `study_reflection_saved`, `review_card_created`, `review_completed`. Визит — случайный UUID в памяти, он меняется при новом запуске, выходе, смене аккаунта или после 30 минут без подтверждённых действий. Одинаковое наблюдение в визите дедуплицируется; повтор после ошибки использует прежний ключ.
- События хранятся внутри PostgreSQL. В теле допустимы только установленное имя, UUID визита, технический ID материала, пресет и признак наличия результатов. Владелец берётся из сессии сервером. Для события открытия проверяется принадлежность материала. В агрегатах отсутствуют идентификаторы и содержимое. Удаление аккаунта удаляет события каскадно. Удаление материала оставляет технический факт, чтобы сохранить знаменатель наблюдаемой когорты. Внешние сервисы аналитики не подключены.
- Флаг `LEARNING_METRICS_ENABLED=false` контролирует запись на сервере. Клиентский сбор по умолчанию выключен и включается при сборке через `EXPO_PUBLIC_LEARNING_METRICS=1`. Условия уведомления участников, срок хранения сырых событий, доступ к БД и итоговым агрегатам подтверждаются до включения на пилоте. [Контракт API](api.md#события-учебного-пилота)

### Метрики

Команда `python -m app.metrics --learning` печатает только агрегаты. Дата начала — первая наблюдаемая запись в UTC. Старые данные не реконструируются. Событие сохранения учитывает успешное создание материала, включая PDF и офлайн-очередь после её серверного подтверждения. Библиотечный импорт восстанавливает ранее существовавшие материалы и не формирует новые когорты.

| Метрика | Определение |
| --- | --- |
| Weekly Active Learners | Число аккаунтов с первым наблюдаемым переходом сохранённого материала в «Изучено» за локальную календарную неделю. Требуется пара событий сохранения и изучения. День события фиксируется в зоне аккаунта при записи. Текущая неделя считается в текущей зоне аккаунта. |
| Активация за 7 дней | Среди наблюдаемых регистраций, у которых полностью прошло 7×24 часа, доля тех, кто сохранил и впервые изучил хотя бы один материал в этом интервале. |
| Save-to-study 7d | Среди наблюдаемых сохранений с полным окном 7×24 часа доля материалов с первым изучением до конца этого окна. |
| Время до первого изучения | Медиана часов от наблюдаемой регистрации до первого изучения материала, сохранённого после регистрации. Показан объём выборки. |
| Первый возврат в другой визит | Среди пользователей зрелой 7-дневной когорты с подтверждённым мобильным визитом доля тех, у кого за первые 7×24 часа было минимум два визита. |
| D7/D30 продукта и обучения | Точно на 7-й или 30-й локальный календарный день после зарегистрированного события. Текущий незаконченный день исключён. Продукт — событие или существующий активный день. Обучение — первая отметка изучения или подтверждённый ответ при повторении. |
| Начатые рекомендации | Среди сочетаний «аккаунт, визит, бюджет» с показанным непустым подбором доля тех, где открыт материал из этого подбора. |

Счётчики создания целей, связей, карточек и повторений отражают подтверждённые события. Целевые значения определяются после первого реального замера. При пустом знаменателе отчёт показывает «нет данных». Как и исходный отчёт `app.metrics`, отчёт пилота агрегирует записи в памяти и рассчитан на небольшой закрытый пилот.

### Миграция и управление выпуском

Ревизия `y5b7d9f1a3c4` добавляет одну таблицу и индекс поверх `x4a6c8e0f2b3`. Существующие данные сохраняются, таблица создаётся пустой. Откат схемы допускается при пустой таблице. При записи событий откат приложения сохраняет аддитивную схему и собранные данные. Один из способов выключения сбора — установить `LEARNING_METRICS_ENABLED=false` и пересоздать только API с согласованием оператора. Для отката мобильной навигации собирается предыдущая принятая версия с увеличенным Android versionCode и тем же сертификатом, чтобы установить её поверх текущей сборки с сохранением данных.

С согласия владельца тестовый стенд обновлён после восстановления парной копии и проверки миграции. HTTPS-прогон с двумя синтетическими аккаунтами прошёл, сбор событий выключен. 26.11.2026 владелец подтвердил короткую проверку учебного цикла на APK 0.15.0. До внешнего пилота нужна расширенная ручная Android-регрессия и решение по открытым каналам, условиям измерения и подписи. Публикация и production требуют отдельного решения.

# Teleiosis как система самостоятельного обучения

Проверка начата 26.11.2026 на `main`, базовая ревизия `e1307b6`, мобильный клиент 0.11.1. Источник требований — [технический план](../TELEIOSIS_PLAN.md).

## E0. Архитектура и переиспользование

| Область | Реализация и решение |
| --- | --- |
| Клиент | Expo 58, Expo Router, React Native 0.88, TypeScript. Переиспользуем `LibraryAccess`, `AuthController`, общий HTTP-клиент, `Page`, `Card`, `Action`, тему и словари RU/EN. Детали материала, план, повторение, добавление и прогресс открываются существующими маршрутами. |
| Идентичность и кэш | FastAPI `CurrentUser` разрешает мобильную Bearer-сессию и веб-cookie по действующим правилам. SecureStore хранит учётные данные. SQLite хранит снимки по ключу «API origin + ID пользователя» и локальную очередь. Переиспользуем чтение кэша, поколение владельца и сброс при выходе. |
| Материалы | PostgreSQL и SQLAlchemy `Content`, API `/contents`. Статусы `unseen`, `planned`, `studied`, `irrelevant`. `planned` сам по себе не содержит даты. Alembic `v2e4a6b8c0d1` добавляет nullable длительность видео и размер текста. HTTP-схема `ContentOut` рассчитывает время чтения как округление вверх по 1000 знаков на минуту. Детали материала используют действующие проверки ссылок и доступ к PDF. |
| План | `/mobile/plan` отдаёт одну неделю с понедельника. `StudyTask` связывает владельца, цель и материал через составные FK. Приоритет 1 выше 2 и 3. Перенос меняет `day`, завершение заполняет `completed_at`, история версионируется. Завершение задания и статус материала независимы. |
| Цели | `StudyGoal` живёт без привязки к неделе. У владельца уникальное имя без учёта регистра. Цель связана с материалами через задания, удаление цели каскадно удаляет задания и историю. Состояния, результат и независимые от заданий связи появятся только по отдельному решению E2. Существующий срок жизни позволяет рассмотреть расширение `StudyGoal`. Перед E2 нужно согласовать архивирование и семантику старого DELETE. Лимит текущего API составляет 100 целей. Уникальность пары «цель + материал» в заданиях важна для дальнейшего повторного планирования. |
| Повторение | `/mobile/review` пагинирует карточки и отдаёт общее число доступных. Доступность определяется владельцем, отсутствием паузы и сроком до текущего локального дня включительно. `again` оставляет карточку доступной, `remembered` переносит по действующим интервалам. |
| Прогресс, время и фоновые задачи | `/mobile/reading-progress` считает изученные материалы за календарную неделю по IANA-зоне аккаунта. `/stats` использует скользящее 7-дневное окно. Недельный план отдельно считает выполненные задания. `app/digest.py` и `app/metrics.py` обслуживают подборки и технические показатели, экран читает первичные данные. |
| Экспорт и импорт | Экспорт включает план, историю, карточки и ответы. Импорт библиотеки обрабатывает материалы и связанные библиотечные данные, восстановление плана и карточек через него не предусмотрено. E1 не меняет форматы. |

## E1. Решения

- Добавляем авторизованный read-only `GET /mobile/learning/today` с локальной датой и зоной, одним занятием, доступными карточками и недельным прогрессом. API плана ограничен одной неделей, а вычисление на клиенте потребовало бы обхода истории и библиотечных страниц. Используем серверные выборки с фильтрацией по владельцу и ограничением выдачи. Таблицы, версии записей и прежние ответы API сохраняются.
- Незавершённые задания до сегодня включительно упорядочены по дате, приоритету и ID. Явное задание по изученному материалу имеет отдельную причину. Если подходящего задания нет, сначала берём материал со статусом `planned`, затем `unseen`, по дате добавления и ID. Открытые будущие задания резервируют материал для своей даты. Статус `irrelevant` исключён из выдачи. Отдельные признаки позволяют различить пустую библиотеку, отложенное обучение и отсутствие актуальных материалов для рекомендации.
- Длительность задания берём из его оценки. Для материалов без задания берём длительность видео, округлённую вверх до минуты, или текущую оценку чтения. При отсутствии обоих значений показываем «Время неизвестно».
- Главный маршрут `/` открывает «Сегодня». Библиотека остаётся отдельной вкладкой на `/library`. Ссылки деталей `/library/[id]`, добавления, прогресса, профиля, входящих материалов, плана, повторения и действий из писем сохраняют пути. Внутренние переходы с назначением «Библиотека» обновляются.
- Один снимок экрана сохраняется в SQLite-кэш с ключом владельца. Обновление на фокусе перечитывает данные после сохранения, завершения, переноса, изменения пояса или ответа на карточку. Возврат приложения на передний план и синхронизация очереди тоже запускают запрос. При сетевой ошибке или 5xx показываем собственный снимок с отметкой устаревания. Без снимка остаются навигация и retry, а недоступные показатели не подменяются нулями. Карточка материала в офлайне использует уже скачанные детали или страницы библиотеки. План, ответы на карточки и получение PDF сохраняют прежние требования к сети.

## E2. Долгосрочные цели

Вкладки «Сегодня», «Библиотека», «Цели», «Профиль». «Добавить» доступно из «Сегодня» и библиотеки, «Прогресс» из «Сегодня» и целей. Маршруты добавления, прогресса и Share сохранены. Из цели можно выбрать существующий материал или запланировать связанный через прежнюю форму недельного плана с выбранной целью. Из карточки материала можно назначить или снять несколько связей.

Расширена существующая `StudyGoal`. Новый результат необязателен, завершение и архивирование основаны на явном действии. Текущие задания и их история при архивации сохраняются. Отвязка материала сохраняет задания и материал, удаление материала каскадно удаляет его связи. Составные FK проверяют владельца обеих сторон. Прогресс считается по уникальным актуальным материалам, исключая «Неактуально». Чтобы не дублировать статистику недели, недельный прогресс продолжает считаться по материалам и заданиям независимо от количества целей.

## E3. Завершение изучения

Кнопка «Отметить изученным» открывает подтверждение на карточке материала. После возврата из браузера или просмотрщика PDF приложение один раз предлагает завершить изучение. Закрытие подсказки сохраняет прежний статус. На Android отслеживаются возврат из внешней активности и фокус окна. На iOS закрытие Quick Look дополнительно подтверждается действующей нативной функцией просмотра.

При входе из «Сегодня» или строки плана сохраняется ID конкретного задания. Сервер в одной транзакции проверяет владельца, материал, версию и связь с этим заданием, фиксирует завершение материала и выбранной задачи и записывает ключ запроса. Из библиотеки по умолчанию меняется только материал. Пользователь может явно выбрать одно открытое задание активной цели. Действующие ручные изменения статуса и задания сохраняют свою семантику. Снятие статуса обнуляет прежнюю отметку изучения для статистики, сохраняя задачу, её историю, карточки и мысль.

Подтверждённое завершение открывает необязательную главную мысль, действующую форму карточки, библиотеку и «Готово». Главная мысль хранится отдельно от заметки. В режиме без сети завершение остаётся неподтверждённым. Ввод мысли сохраняется в SQLite под ключом аккаунта и материала и отправляется только по явной команде после восстановления связи. При конфликте доступны обе версии. Выход с локальным черновиком требует подтверждения удаления. [Контракт API](api.md#завершение-изучения)

### Миграция и откат

- `x4a6c8e0f2b3` после `w3f5b7d9e1a2` добавляет `content_reflections` и `learning_completions` с составными внешними ключами владельца и материала. Старые таблицы, данные и форматы маршрутов сохраняются. Серверная миграция не копирует заметки и не присваивает мысли задним числом.
- На стенде перед применением требуется отдельное разрешение, восстановление парной копии PostgreSQL/PDF в изолированную БД, сверка данных и испытание миграции. При откате возвращается образ E2, аддитивная схема остаётся. Downgrade останавливается при наличии мысли или квитанции завершения.
- Экспорт v1 включает мысли с `content_id`. Технические ключи повторов в экспорт не входят. Библиотечный импорт сохраняет действующий охват и не восстанавливает мысли.

## Серверный контракт

Только native Bearer, без Cookie, Origin и Sec-Fetch-Site. Закрытый шлюз использует существующую ветку `/mobile/*`. Пароль шлюза остаётся в `X-Staging-Authorization` и удаляется Caddy перед API.

- `PUT /mobile/devices/{uuid}` принимает `{token, enabled}`. UUID клиент хранит отдельно для каждой пары установки и аккаунта. Ответ содержит только `{id, enabled}`. При выключенном feature flag возвращается 503. Лимит 10 устройств на аккаунт. UUID другого владельца даёт 409.
- Ротация токена обновляет регистрацию. Перенос одного provider token на другой UUID удаляет старую регистрацию и её квитанции. Выход/отзыв сессии и удаление аккаунта удаляют устройство каскадом.
- `DELETE /mobile/devices/{uuid}` идемпотентно удаляет только собственное устройство, доступен при выключенном flag.

Все устройства этой версии относятся к RuStore. Для APNs потребуется явное расширение модели/контракта. Ни токен устройства, ни сервисный токен API не возвращает.

## Доставка

Миграция `m4c6d8e0f2a3` создаёт `push_devices` и `push_deliveries`. Уникальность `(device_id, event_key)` предотвращает повторное планирование. Квитанция хранит статус, число попыток, следующий срок и ограниченную причину без ответа провайдера. Завершённые квитанции удаляются через 30 дней. Токен нужен в БД для отправки и удаляется при отзыве регистрации.

Worker сначала обрабатывает push, затем существующую почту. Для напоминания TTL 24 часа, для ежедневной подборки 3 часа. Push включается только отдельным opt-in устройства. Настройка `reminders_enabled` продолжает управлять почтой. Будущий интерфейс должен явно показывать оба канала и предупреждать о включении обоих. Пока UI отсутствует, push по умолчанию полностью выключен.

Новые push планируются по ожидающим напоминаниям перед почтовым проходом. Уже созданная квитанция может повторяться, когда почта пометила напоминание отправленным. Старые напоминания, обработанные почтой без push-квитанции, заново в push не планируются.

Перед каждой попыткой проверяются владелец, мобильная сессия, доступность материала, статус, отмена/перенос напоминания и настройки устройства. События до включения устройства не отправляются. Изменение напоминания отменяет активные квитанции. Изученный материал не отправляется при повторе.

HTTP 200 означает принятие провайдером, а не доставку на телефон. Ошибки сети, 429 и 5xx повторяются с экспоненциальной задержкой и jitter. Просроченная попытка прекращается по TTL. Зависшая попытка освобождается через 45 секунд. Невалидный токен отключается, ошибки авторизации/запроса завершают попытку без удаления токена. Payload содержит общую фразу и ID материала/доставки, без названия, заметки, ссылки и почты.

После потери ответа провайдера возможен дубль. Отменить уже принятое провайдером сообщение нельзя. Нужна проверка актуальных прав при открытии карточки. Exactly-once и доставка с точностью до секунды не обещаются.

## Включение и открытые проверки

Автоматически прошли 794 backend-теста за 26.94 с, включая 25 push-проверок. PostgreSQL и тестовые БД были изолированы от стенда. Миграция прошла upgrade → check → downgrade до `l3b5c7d9e1f2` → upgrade → check без расхождений metadata. Проверены Compose config с вымышленными значениями, Python compileall и git diff --check. Отправитель провайдера в тестах заменён, реальной отправки не было. Мобильные проверки в этом проходе не запускались, клиентский код и зависимости не менялись.

Compose передаёт `PUSH_ENABLED`, `RUSTORE_PROJECT_ID`, `RUSTORE_SERVICE_TOKEN` из приватного окружения API/worker. Включение без ID и сервисного токена не проходит валидацию настроек. Ни один рабочий env не изменён.

Перед отдельно согласованным rollout нужны резервная копия/проверка миграции, обновление API и worker, настроенный проект, совместимый клиент и проверка секретов/доступа через шлюз. Требуются реальные send/receive, отказ permissions, token rotation, foreground/background, холодный запуск после уничтожения процесса, logout, несколько устройств и ограничения сети/энергосбережения S25. APNs и все проверки физического iPhone открыты.

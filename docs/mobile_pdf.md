# Подблок 9В — PDF-материалы

## Уточнение сценария в 0.8.1 — 21.11.2026

Пользователь проверил APK 0.8.0 и попросил создавать PDF отдельным видом материала. Для проверки на стенде 0.8.0 показывал общую ошибку, потому что маршрут PDF отсутствует в текущем API 9А. В новой форме приложение сначала проверяет доступность создания PDF и показывает причину до открытия системного выбора.

## Локальный контракт

Пользователь принял результат 9Б и разрешил перейти к 9В. Выбор российского провайдера, стоимость и развёртывание требуют отдельного решения. Для локальной разработки используется совместимый с S3 тестовый сервис и вымышленные PDF.

- При создании пользователь выбирает «Ссылка», «Заметка» или «PDF». PDF создаёт отдельную карточку с одним файлом. Название по умолчанию берётся из имени файла. Категорию можно выбрать в форме, теги и коллекции назначаются после сохранения. Обычные ссылки, включая ссылки на PDF, сохраняются по прежнему сценарию.
- Предельный размер 10 МиБ, квота 20 PDF и 100 МиБ на аккаунт. Квота учитывает незавершённые загрузки. API проверяет `application/pdf`, подпись, структуру документа и результат антивирусной проверки. Зашифрованные, повреждённые и активные документы отклоняются. Сканер обязателен при включённой функции. При недоступном сканере загрузка завершается ошибкой.
- `GET /mobile/library/pdf` сообщает доступность, `POST /mobile/library/pdf` принимает файл и создаёт материал. Метаданные идут через `GET /mobile/library/contents/{id}/pdf`, скачивание через `.../pdf/download`. Байты выдаёт авторизованный API владельцу. Повтор файла в том же аккаунте открывает уже созданную PDF-карточку. Загрузка и чтение работают онлайн.
- Объект в приватном бакете хранится под сгенерированным ключом. Удаление материала или аккаунта закрывает доступ сразу. Отдельная очистка повторяет удаление объектов после сбоев и удаляет незавершённые загрузки. До включения функции должны быть проверены права бакета, хранение и резервное копирование, очистка и восстановление.
- Экспорт JSON включает метаданные PDF. При импорте JSON v1 карточка восстанавливается как заметка с прежним названием и организацией, файл скачивается отдельно. PDF скачивается отдельно из карточки. Поиск ограничен полями карточки. Загрузка всегда идёт через прямой онлайн-запрос.

## Файлы и поведение

Откройте «Добавить материал» → «Вид материала» → «PDF», выберите документ и нажмите «Сохранить». После успешной загрузки откроется новая карточка. Повтор по SHA-256 возвращает существующую карточку текущего аккаунта. Незавершённая загрузка оставляет только временную запись очистки в PostgreSQL. Квота включает объекты аккаунта, ожидающие физической очистки, чтобы циклическая загрузка и удаление не обходили ограничение. Скачивание проверяет размер и SHA-256 перед передачей в системный просмотрщик. Временная копия удаляется при уходе с экрана и на следующем запуске приложения. Системное ПО может создавать собственные копии.

Серверная логика находится в `app/routers/pdf.py`, `app/pdf_storage.py`, `app/pdf_validate.py`, `app/pdf_cleanup.py` и `app/export.py`. Ревизия `q7f9b1c3d5e6` добавляет `pdf_objects`, а `r8a0c2e4f6b7` добавляет состояние незавершённой загрузки и разрешает карточку PDF без URL и заметки. Объект резервируется в PostgreSQL до S3 PUT. После подтверждённой записи сервер публикует карточку и связывает её с объектом в одной транзакции. При удалении материала или аккаунта внешний ключ закрывает доступ, сохраняя ключ объекта для повторяемой очистки. Downgrade останавливается, пока журнал содержит ключи объектов.

Мобильный интерфейс реализован в `mobile/src/app/library/pdf.tsx`, `mobile/src/library/pdf.ts`, карточка материала, навигация и сетевой транспорт. Изменены preview-конфигурация и версии сборки. Проверки размещены в `tests/test_pdf.py`, `tests/test_organization_migration.py`, `mobile/tests/libraryPdf.test.tsx`, `mobile/tests/libraryApi.test.ts`, `scripts/check_pdf_services.py` и проверка транспорта Caddy. Дополнительные зависимости Python закреплены в `requirements.txt`, настройки API добавлены в `app/config.py` и `deploy/compose.yml`.

Парсер принимает статические PDF до 1000 страниц, разбирает структуру в отдельном процессе с лимитами памяти и времени. Отклоняются шифрование, инкрементальные обновления, аннотации, формы, действия и вложенные файлы. ClamAV получает оригинальные байты через закрытый INSTREAM. Ошибка, тайм-аут или отказ сканера останавливают загрузку. Проверка уменьшает риск вредоносного содержимого, а просмотр выполняется системным приложением.

## Подготовка стенда после отдельного согласования

1. Согласовать российского S3-провайдера, стоимость, шифрование, объём, резервирование и ресурсы для ClamAV. Ограничить сеть сканера API и техническим хостом, настроить обновление сигнатур и лимиты INSTREAM/ScanSize для 10 МиБ. Бакет выделенный, приватный, с выключенным версионированием и без публичного доступа. Учётные данные API получают PutObject/GetObject/DeleteObject только на префикс `teleiosis/pdf/`. Способ резервирования объектов и проверка восстановления согласуются отдельно.
2. Снять новый архив PostgreSQL, проверить восстановление отдельной БД и сверить ревизию и счётчики. Если стенд остаётся на 9А, применить последовательно `p6e8f0a2b4c5`, `q7f9b1c3d5e6` и `r8a0c2e4f6b7`. Закрепить локально проверенный образ через `TELEIOSIS_API_IMAGE` после проверки итогового Compose. Маршруты PDF проходят через действующий `/mobile/*`; менять Caddy для них не требуется.
3. Сначала запустить API с `PDF_ENABLED=false` и проверить старый контракт и 9Б. Для включения задать `PDF_S3_ENDPOINT`, `PDF_S3_REGION`, `PDF_S3_BUCKET`, `PDF_S3_ACCESS_KEY`, `PDF_S3_SECRET_KEY`, `PDF_SCANNER_HOST` и при необходимости `PDF_SCANNER_PORT`. Секреты задаются через серверное окружение API. Настроить периодический `python -m app.pdf_cleanup` с тем же бакетом и наблюдением за ошибками.
4. Проверить по HTTPS два вымышленных аккаунта, отказ прямого анонимного доступа к бакету, загрузку статического документа, повтор, счётчики и фактическое удаление после очистки. Проверить резервирование и восстановление базы вместе с объектами. После развёртывания вручную пройти сценарии S25 и iOS.
5. При откате отключить загрузку, вернуть прежний API pin и сохранить применённые миграции, бакет и журнал. Продолжать очистку отдельным запуском проверенного образа с конфигурацией PDF. Downgrade схемы PDF допустим только после подтверждённого удаления всех объектов и опустошения журнала. Восстановление базы и бакета должно восстанавливать один согласованный снимок.

## Подготовка варианта на текущем диске — 21.11.2026

Пользователь разрешил обновление стенда и попросил сохранить текущую стоимость. Локально добавлен режим `PDF_LOCAL_DIR=/var/lib/teleiosis/pdf` для закрытого теста. API пишет в приватный том с правами 0700 и файлами 0600, атомарно публикует байты и ограничивает общий объём PDF одним ГиБ. ClamAV доступен API через Unix-сокет. Сканер запускается отдельным контейнером с лимитом памяти, без опубликованного порта. Для регулярного обслуживания подготовлены отдельные таймеры очистки и парного архива PostgreSQL и PDF. Архивы ограничены по объёму и хранятся на текущем сервере. Промышленный режим сохраняет S3 как обязательное хранилище.

Предварительный backup стенда сохранён в `/var/backups/teleiosis-09c-pdf-i9mszari`. Восстановление отдельной PostgreSQL подтвердило ревизию `n5d7e9f1a3b4` и счётчики 15 таблиц. Образ ClamAV загружен на сервер. Запуск контейнера, миграции и переключение API отложены после отказа в запуске изолированных PostgreSQL-проверок и сборки кандидата. Стенд остаётся на 9А. APK 0.8.1 совместим с API в обоих режимах хранения. Покупки и смена тарифа не выполнялись.

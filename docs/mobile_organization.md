Блок 9 разделён на отдельно принимаемые результаты:

- **9А: организация библиотеки** — теги, коллекции, назначение сохранённым материалам, фильтрация по одному тегу и одной коллекции, экспорт связей и удаление.
- **9Б: импорт и расширенный текстовый поиск** — отдельный контракт форматов, лимитов, дублей и поиска перед реализацией.
- **9В: PDF-файлы** — приватное хранилище в РФ, квоты, MIME/размер/проверка файлов и удаление. Требует отдельного решения по инфраструктуре и стоимости.

Тег — короткая метка, коллекция — именованная подборка. У материала может быть несколько тегов и несколько коллекций; существующая единственная категория сохраняется. Иерархии, совместный доступ, порядок внутри коллекции и новые функции сайта в 9А не входят. Названия уникальны без учёта регистра в пределах владельца и вида; до 50 символов. Лимит — 200 тегов и 200 коллекций на аккаунт, до 20 связей каждого вида у материала. Удаление метки или подборки сохраняет материалы.

Назначение выполняется после сохранения материала, только онлайн. Очередь новых URL/заметок и fingerprint существующих идемпотентных отправок не меняются. При отсутствии сети старая библиотека и очередь доступны как раньше; фильтры по тегам/коллекциям требуют подключения и не выдают нефильтрованный кэш за результат.

## API и совместимость

Новые `/tags`, `/collections` и `/contents/{id}/organization` используют существующий CurrentUser: Bearer для mobile, cookie с CSRF для сайта, запрет смешанных credentials. Мобильные алиасы тех же обработчиков находятся под `/mobile/library/`, который уже проходит через staging-шлюз. Расширять Caddy matcher не требуется. API и две миграции согласованно развёрнуты 20.11.2026; новые функции доступны для приёмки на телефоне. Пароль шлюза удаляется на прокси, Bearer сохраняется. Остальные API и ответы ContentOut, ContentCreate и submissions остаются совместимыми.

Назначение тегов/коллекций требует If-Match версии материала. Конфликт — 412 без частичной записи, чужой/отсутствующий объект — 404. Одинаковый набор связей не меняет версию. Изменение связей или удаление назначенного тега/коллекции повышает версию материала; обычный versioned PATCH видит этот конфликт. Фильтры tag_id/collection_id соединяются по AND с прежними фильтрами, не размножают строки и сохраняют total/пагинацию.

Экспорт JSON расширяется дополнительными массивами тегов/коллекций и связей, без секретов. Формат версии 1 сохраняет прежние поля; новые поля аддитивны. Каскадное удаление аккаунта/материала удаляет связи. Составные FK запрещают связь объектов разных владельцев в самой БД.

- В библиотеке видна отдельная кнопка «Теги и коллекции», в сохранённой карточке — «Теги и коллекции материала». Создание/переименование/удаление групп, множественный выбор, снятие связей и фильтрация реализованы. После возврата из назначения карточка обновляется и получает актуальную version.
- Наборы сохраняются одним versioned PATCH. При 412 выбранные правки остаются видимыми, повторная запись заблокирована до явной загрузки актуальных данных. При потерянном ответе PATCH предлагается сначала перечитать данные. POST автоматически не повторяется; при неопределённом результате создания предлагается обновить список.
